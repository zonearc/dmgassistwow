# Engine priority: SimC-led, Blizzard-backed

Status: agreed direction (2026-11-08). Owner requirement: SimC goes first where it makes sense, because Blizzard's
assistant is safe but leaves out key spells; Blizzard's rules are the safety net, not the authority.

## Data sources (both from github.com/simulationcraft/simc, branches `midnight` and `forever`)

| Source | Path | What it is |
|---|---|---|
| SimC APL | `ActionPriorityLists/default/<class>_<spec>.simc` | Theorycrafted optimal priority (cooldown sync, pooling, variables) |
| Blizzard rules | `ActionPriorityLists/assisted_combat/<class>_<spec>.simc` | Blizzard's Assisted Combat rules, generated by SimC from the game's `AssistedCombat`, `AssistedCombatStep`, `AssistedCombatRule` DBC tables |

The `forever` branch is built from Forever beta game data (build 70425, 2026-10-16) and differs from `midnight` in only
18 of 68 files (mostly spell renames such as `dot.rend` vs `dot.rend_dot`).

## Measured gaps in Blizzard's assistant (midnight branch, 2026-11-05 data)

- **Major cooldowns excluded from the in-game assistant**: 38 of 650 rule lines are marked "for Blizzard automation and
  not included in the game's Assisted Combat system" — every spec's burst button (Berserk, Combustion, Avenging Wrath,
  Recklessness, Trueshot, Metamorphosis, Summon Infernal, ...).
- **Spells absent from Blizzard's rules**: only 329 of 481 SimC abilities (68%) appear in them. Missing: interrupts,
  execute-phase spells (e.g. Hammer of Wrath), talents (Storm Bolt, Champion's Spear), forms/stealth openers.
- **Ordering**: Blizzard's lists are flat "first true line"; SimC sequences cooldowns and pools resources.

## Decision procedure (each GCD)

Every condition term is evaluated three-valued against one shared state model:

- `TRUE` / `FALSE` — readable from the game, or tracked by us with good confidence.
- `UNKNOWN` — hidden in combat and not reliably modelled.

1. Walk the SimC APL top-down.
   - Line fully `TRUE` → **recommend it. Blizzard cannot override a confident SimC pick.**
   - Line `UNKNOWN` → a *maybe*. Accept only if corroborated: on Midnight the live `C_AssistedCombat.GetNextCastSpell()`
     names the same spell; on Forever our evaluation of Blizzard's rule for that spell is `TRUE`. Otherwise skip.
   - Line `FALSE` → continue.
2. Nothing confident from SimC → **Blizzard's pick** (live assistant on Midnight; our evaluation of Blizzard's rules on Forever,
   where the in-game assistant is switched off).
3. **Major cooldowns** come only from SimC and are shown in a separate Cooldowns slot (Hekili-style), gated by a burst
   toggle, never buried under fillers.
4. Slots 2–3 of the queue: advance the modelled state by the chosen cast (cost, cooldown start, buff applied) and repeat.

## Assistant as oracle (Midnight only)

The assistant is secure code and can read secret state. Its rules are known exactly, so its pick implies facts:
if it recommends rule line *k*, then line *k*'s condition is true and every enabled line above it is false.
Example: it recommends Rip → Rip is not ticking on the target and combo points ≥ 5. These inferred facts feed the state
tracker as observations with high confidence (until the next state change).

## Readability classes (filled in by the importer's coverage report)

| Term family | Example | Class |
|---|---|---|
| Secondary resources | `combo_points`, `holy_power`, `runes`, `chi`, `soul_shards`, `essence` | read (to be confirmed by probe) |
| Cooldown ready / charges | `cooldown.x.ready` | read via `isActive`; remaining time tracked from own casts |
| Talents, hero tree | `talent.x` | read (out of combat, cached) |
| Our own buffs from our casts | `buff.tigers_fury.up` | tracked (cast + known duration), resynced by glows/whitelist |
| Procs | `buff.apex_predators_craving.up` | glow events where the proc lights a button; else unknown |
| Our DoTs on the target | `dot.rip.ticking` | tracked per target while target unchanged; oracle on Midnight |
| Primary resource | `energy`, `rage`, `astral_power` | modelled (regen + costs), resynced by `IsSpellUsable(...).insufficientPower` |
| Range | `target.distance<=8` | `C_Spell.IsSpellInRange` (secrecy to verify) |
| Enemy count | `active_enemies`, `spell_targets` | user mode toggle ST/AOE/AUTO; nameplate count if readable |
| Target health / time to die | `target.health.pct`, `fight_remains` | unknown (UnitHealthPercent with curves may help — research) |

## Feedback loop

Every GCD the engine logs to the Watchdog (`DMGAssistWatchdog.Log`): SimC pick, Blizzard pick, what was actually cast,
and the UNKNOWN terms on the path. Agreement rate per spec and per term shows where tracking must improve.

## Legacy contrast

The 2026 engine ranked the assistant first ("AC Recommendation Is the Highest Authority", hand-tuned scores -12000 /
-11500 / -11000 ...). That inverted the owner's intent and is the likely reason SimC-only spells were starved.

## Implementation (0.1.0, 2026-11-08)

| File | Job |
|---|---|
| `Core/Expr.lua` | SimC expression parser (same grammar as the importer) + three-valued evaluator; parses every condition in both data branches (tested) |
| `Core/SpellMap.lua` | SimC names -> the player's spell IDs and talents, by tokenizing spellbook and talent-tree names like SimC; aliases (`bs_inc`) and suffixes (`_cat`) |
| `Core/State.lua` | Resolver for SimC terms; trackers: own casts (event, or cooldown-edge inference when the event is secret), learned cooldown and aura durations (saved per spec), cast -> aura links, clock resync + drift counts, haste-based GCD |
| `Core/Engine.lua` | The decision procedure above: SimC walk with variables and action lists, corroboration, Blizzard fallback, cooldown slot |
| `Core/Display.lua` | Main icon + cooldown icon; labels `AC` (assistant), `B` (Blizzard rules), `?` (guess) |

Assumptions standing in for unreadable facts (class M): `target.distance` = 5 (SimC's own default), target count from
`/dmga mode st|aoe|auto` (`auto` counts hostile nameplates in combat when readable), fight length from `/dmga fight`,
`fight_style.patchwerk`, no raid events, items/trinkets/set bonuses = 0 (items are not recommended yet).

Not yet: queue slots 2–3 (state advance), using glows as proc evidence, the assistant-as-oracle inference, pooling
(`pool_resource`), `target_if` multi-target selection, healer/defensive/interrupt advice (task: legacy review).

## Update (2026-11-08, later): SimC spell data, look-ahead, modes, languages

- **Spell data from SimC.** `tools/simc_spells.py` parses `SpellDataDump/<class>.txt` (plus the class's entries in
  `allspells.txt`, which has spells the class dump omits) into per-spell facts: cooldown (and whether haste shortens it),
  charges, GCD, duration, cast time, resource costs (finishers: min–max), resource gains, and the auras a spell applies
  to the player or the target (directly or via a triggered spell). Per spec only the spells its lists reference are
  emitted (`record.spells`, `record.spellInfo`, `record.heroTrees`). 92%+ of SimC action names map to spell IDs; the rest
  are SimC pseudo-actions (`retarget`, `pick_up_fragment`, `cycling_variable`) or pets/poisons.
- **Language independence.** The spell map matches by spell ID against the spellbook and talent tree; hero trees by
  their talents' IDs. English-name tokens remain only as a fallback.
- **Look-ahead.** `State.BeginLookahead` overlays a future moment: clock shifted, cooldowns started, auras applied,
  costs paid (finishers empty their resource even when its value is secret), gains added, `prev_gcd` updated. Slot 1 is
  evaluated at the end of the current GCD / cast with the spell being cast already counted; slots 2–3 chain from there.
  Not modelled yet: passive resource regeneration (energy/focus/runes), procs, charge counts, cooldown reduction effects.
- **Target modes.** Primary mode ST/AoE (user setting), auto-detect from hostile in-combat nameplates (`nameplate1..40`)
  when readable, a key binding to cycle Auto → ST → AoE. When auto can't count, the primary mode applies.
- **Languages.** Messages and key-binding names in 9 locales (`Core/Locales.lua`); missing strings fall back to English.

## Clues: inferring hidden state (Core/Clues.lua)

| Clue | Where it comes from | What we learn | Checked against |
|---|---|---|---|
| Assistant oracle (Midnight) | `C_AssistedCombat.GetNextCastSpell` + Blizzard's rules in our data | The rule for its pick is TRUE; every earlier rule whose spell is castable is FALSE → buff/DoT up/down, resource ranges (`combo_points>=5` false → ≤ 4) | Readable aura scans and resource values (out of combat, where the assistant also works) |
| Proc glows | `SPELL_ACTIVATION_OVERLAY_GLOW_SHOW/HIDE` (plain spell IDs) | Which buff each glow means (learned out of combat, saved per spec); in combat glow = buff up, glow gone = buff consumed | Readable aura scans |
| Affordability | `C_Spell.IsSpellUsable` (isUsable, insufficientPower), not secret | Hidden resource ranges from single-cost spells (SimC costs); glowing spells skipped (procs make them free) | Readable resource values |

Expressions use the ranges directly: `combo_points<5` is decided when combo points are known to be 0–4.
Oracle facts live 1 s and are dropped when we cast; glow facts last until the glow ends. Every source is graded each time
the truth is readable; one that is wrong > 20 % of the time (after 20 checks) is switched off for the session and logged.
Remembered "buff is down" is certain only for auras our own casts apply; for procs it decays to unknown.

Haste/crit: haste is read when `UnitSpellHaste` is readable (and remembered when not) to scale GCDs, cast times and
hasted cooldowns; crit only changes proc odds, which these clues observe directly rather than predict.
